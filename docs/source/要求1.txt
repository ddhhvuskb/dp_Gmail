一、目标与边界

做：本地优先跨平台桌面邮件客户端，统一多邮箱，国内邮箱开箱即用。
不做：Web/移动/服务端/日历/联系人/PGP。

二、技术栈锁定（不得变更）

构建 GitHub Actions 矩阵 —

三、模块边界与接口

```
src-tauri/src/
├── mail/        IMAP/SMTP/解析/provider
├── storage/     表结构/CRUD/FTS5
├── security/    加密/HTML净化
├── ai/          只读，可选
└── commands/    Tauri桥，只做参数校验和转发

src/
├── components/  通用UI
├── features/    accounts/inbox/compose/search/settings
├── stores/      Zustand
└── lib/         工具
```

接口规则：

· 跨模块调用必须走已定义函数签名，禁止访问内部数据结构。
· commands/ 不写业务逻辑，只做转发。
· ai/ 只能读，不能发信/删除/修改；输出需人工确认才可写。

调用契约表：

调用方 被调用方 接口方式 定义位置
前端 → Rust Tauri Commands #[tauri::command] commands/
commands → mail Rust函数 同步/异步 mail/mod.rs
mail → storage Rust函数 同步 storage/mod.rs
ai → storage 只读查询 只读函数 storage/message_store.rs

五、AI协作规则（防作妖核心）

5.1 任务粒度

· 一次只生成一个函数或组件，≤50行。
· 不得提前实现后续任务，不得生成占位代码。

5.2 每次Prompt必须包含的约束块

```
【角色】Rust/TS开发工程师
【任务】具体任务
【输入】字段名、类型、示例
【输出】函数签名、返回类型
【约束】
  - 只生成一个函数/组件
  - 指定crate/库
  - 错误处理返回Result
  - 不改已有文件
【验收】可测试标准
【禁止】本任务特有禁止项
```

5.3 防幻觉三层

1. 输入输出未明确 → 停下问，不猜。
2. 跨模块调用前先读接口定义，确认签名。
3. 生成后必须运行 cargo check 或 tsc --noEmit。

5.4 常见AI错误模式与拦截

错误模式 表现 拦截规则
API幻觉 调用不存在的crate函数 先查crate文档确认函数存在
架构漂移 自行增加新模块或依赖 新依赖必须在Cargo.toml已声明
上下文遗忘 覆盖之前已完成的代码 改文件前先读当前内容
过度设计 简单任务引入复杂抽象 函数≤50行，组件≤100行
编码不一致 命名风格混用 强制rustfmt + prettier
硬编码 服务器地址/端口写死 服务商配置从provider.rs读
