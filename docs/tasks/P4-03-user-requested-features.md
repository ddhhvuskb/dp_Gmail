## 1. 主题切换：白天 / 黑夜模式

**诉求**：现在只有一种配色，夜里太亮。需要能在设置里切换明/暗。

| 项 | 评估 |
| --- | --- |
| 新增依赖 | **不需要**（CSS 变量 + 现有 Zustand） |
| 改动范围 | `src/styles`（颜色抽成变量）+ 新增 `stores/theme.ts` + 一个开关 UI |
| 持久化 | `localStorage` 存主题标识 —— **不是密码，符合规范** |
| 风险 | 低。纯展示层 |
| 规模 | 小（半天内） |

**建议先做这一项**：投入最小、用户立刻能看见效果、不牵动任何其他模块。

## 2. 多语言：中文 / 日语 / 英语

**诉求**：现在只有中文，需要能切换语言。

| 项 | 评估 |
| --- | --- |
| 新增依赖 | **不需要**（一个字典对象 + 现有 Zustand + 一个 `t()` 函数） |
| 改动范围 | **跨切面**：约 15 个组件里的所有用户可见字符串都要抽出来 |
| **隐藏成本** | **Rust 侧的错误消息也是用户可见的**，且现在是硬编码中文（`commands/` 返回的 `String`）。要做到真正多语言，这些也得改 —— 那会动 `commands/` 的返回契约 |
| 风险 | 中。漏抽一处就出现中英混排；Rust 错误不改的话，出错时仍是中文 |
| 规模 | 大。建议分两步：先做前端 UI 字符串，再决定 Rust 错误消息怎么办 |

**必须先定一件事**：Rust 侧错误消息要不要一起多语言？
- 要 → 需要改 `commands/` 返回结构（比如返回 `{code, params}` 而不是成品字符串），
  这是**接口签名变更**，且影响所有 9 个命令。
- 不要 → 前端多语言了，但报错仍是中文。这是个**半成品**，需要用户知情。

## 3. 编译成手机版

**诉求**：要能在手机上跑。

**这是四项里唯一的大工程，且有硬性物理限制。**

### 3.1 平台可行性

| 平台 | 在**这台 Windows 机器**上能否做 | 说明 |
| --- | --- | --- |
| **Android** | 🟨 技术上可行 | 需安装 Android SDK + NDK + JDK，并执行 `tauri android init`。安装量大，且本机未验证过 |
| **iOS** | ⛔ **不可能** | 编译 iOS 必须有 **macOS + Xcode**。Windows 上无论装什么都不行 |

### 3.2 不只是「加个构建目标」

| 障碍 | 说明 |
| --- | --- |
| **数据目录** | 现在用 `%APPDATA%\com.dpgmail.desktop`。移动端沙箱路径完全不同，`DP_*` 路径逻辑要重写 |
| **密钥文件** | `key.json` 现在落在应用数据目录。移动端要考虑是否能放系统钥匙串 |
| **界面布局** | 现在是**三栏**（侧栏 + 列表 + 详情）。手机屏幕放不下，需要重做成「列表 → 点进详情」的单栏导航 |
| **`bundled` SQLite** | 需要 NDK 交叉编译，本机未验证 |
| **OAuth / 系统浏览器** | 若后续做 P3-02，移动端的回环回调机制与桌面不同 |

### 3.3 结论

**这不是「编译一下」的事，是一次平台移植。** 而且它超出了 `DESIGN.md` 里
「本地优先跨平台**桌面**邮件客户端」的既定范围 —— 按 `AGENTS.md`「授权例外」第 2 条，
属于超出锁定范围的重大事项，**必须由用户明确决定是否纳入本项目**，并新开 ADR。

建议：先做桌面端的 1 和 2，手机版单独作为一个阶段排期。

## 4. 打开时先弹 CMD 窗口 —— **已诊断，不是 bug**

**现象**：双击程序后先出现一个黑色命令行窗口，然后才是主界面。

**原因**：用户运行的是 **debug 构建**。`main.rs` 里这段是对的：

```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]
```

但它**只在 release 构建生效**。PE 头实测：

| 文件 | Subsystem | 是否弹控制台 |
| --- | --- | --- |
| `target\debug\dp-gmail.exe` | 3 = `WINDOWS_CUI` | **是** |
| `target\x86_64-pc-windows-msvc\release\dp-gmail.exe` | 2 = `WINDOWS_GUI` | 否 |

**处理**：不需要改代码。给用户一个当前代码的 release 产物即可。
（旧的那个 release 是几轮前的，缺分页、企业邮箱、新浪条目等改动，已重新构建。）
