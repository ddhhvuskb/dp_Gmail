| Job | 内容 |

| `build` | 矩阵 `[x86_64-pc-windows-msvc, aarch64-pc-windows-msvc]`，各自 `npm run build` 后 `cargo build --release --target …` |

---

## 2. 一个必须写进流程的顺序约束

**`cargo build` 之前必须先 `npm run build`。**

`tauri-build` 在编译期校验 `tauri.conf.json` 的 `frontendDist`（`../dist`）**必须真实存在**，
否则构建脚本直接失败 —— 这一步在 P0-04a 已经踩过一次。
CI 里若把 Rust 构建放在前端构建之前，会稳定复现该失败。

同理，`check` job 里虽然只跑 `cargo check`，但那也会展开 `tauri-build`，
所以该 job 同样先跑了 `npm ci`。

---

## 3. 矩阵设计

| 目标 | 说明 |
| --- | --- |
| `x86_64-pc-windows-msvc` | 主流桌面 |
| `aarch64-pc-windows-msvc` | Windows on ARM |

`fail-fast: false` —— 一个目标挂掉时另一个继续跑完，
否则只能看到先失败的那个，无法判断 ARM64 到底断在哪一步。

最后一步会校验 `dp-gmail.exe` 确实存在并打印体积，
避免「编译通过但产物没生成」这种假绿。
