## 4. 必须知道的两个阻塞

### 4.1 QQ 授权码（硬阻塞）

**这是最大的风险来源。** `fetch_recent` 与 `send_mail` 合计约 150 行网络代码，
**零真实执行** —— TLS 握手、AUTH、DATA、IMAP SELECT/FETCH 全都没跑过。

现有测试只覆盖到：参数校验、校验顺序、MIME 组装、附件读写、超时分支、问候语校验。
**没有任何一次真实握手。**

获取方式：mail.qq.com → 设置 → 账户 → 开启 IMAP/SMTP 服务 → 生成 16 位授权码。

拿到后可在一轮内验证：真实收信、真实发信、端到端回复。

### 4.2 企业邮箱方案（待决策）

企业邮箱（腾讯企业邮 / 网易企业邮 / 阿里云）**用的是客户自己的域名**，
现有 `ProviderConfig.domains` 的自动识别对它们**完全无效**。

两条路：

- **方案 A（推荐）**：`resolve_by_email` 返回 `None` 时，前端提示「未识别到服务商，请手动选择」并给下拉列表。改动小，复用现有结构。
- **方案 B（不建议）**：对未知域名猜 `imap.<domain>` 并连接探测。**这是拿用户密码去戳未知服务器，猜错等于把凭证发给错误的服务器** —— 安全问题，不是体验问题。

详见 `docs/tasks/P3-01-provider-compat.md` §5。

## 6. 别忘了这些坑

### 6.1 Windows / PowerShell

- **不要用 PowerShell 改 UTF-8 源码或文档** —— `Set-Content -Encoding UTF8` 会把中文写成乱码（本会话栽过两次）。
- **不要用 PowerShell 的 grep 输出判断文件是否损坏** —— PS 5.1 控制台按 GBK 解码，读 UTF-8 必然乱码，哪怕文件完全正常。用 `read` 工具确认。
- **提交信息含引号时用 `git commit -F <文件>`** —— 否则 PowerShell 的参数传递会被破坏。

### 6.2 UI 自动化（实跑验证用）

- **中文输入法会截走 `SendKeys` 的字符**，候选框还会盖住按钮。改用剪贴板 `^v` 粘贴，并先发 `{ESC}`。
- **坐标必须从实拍截图量，不能凭旧截图推算** —— 加一个按钮就会让整个侧栏下移。

### 6.3 开发过程本身

- **底层测通了不等于上层测通了。** 本会话至少三次踩到：`build_message` 私有导致 HTML 路径零覆盖；`load_attachments` 私有；163 加了模块层测试但命令层没测。**加测试前先问：这个功能从哪个入口被调用？我测的是那个入口吗？**
- **规则写下来 ≠ 规则被执行。** `AGENTS.md` 加了「每个任务文档必须写明未验证边界」后，四轮之后才发现 4 份最早的文档根本没写。
- **文档会悄悄过期。** 本会话修正过 5 处与代码不符的状态（含同一任务 ID 在两处一处 ⛔ 一处 ✅）。阶段收尾时按 `AGENTS.md` 的「文档审计」清单过一遍。
